## 1. 已确认范围与不可突破的费用约束

### 1.1 目标

同一真实主题项目能保留经审阅的图文稿，派生独立口播稿，并产出 2～5 分钟可直接使用的单人音频。成员可以按段试听和修订；修改一个口播段落只重新合成受影响段落。重启后保留稿件、声音设置、音频与任务记录，失败可按明确规则恢复或安全重试。

复用 V1.0+ 的成员、项目 ACL、素材、人工审核、定稿权限、任务运行和备份基础，不重复建设团队协作，不更换现有技术栈来实现 TTS。

### 1.2 MiniMax 与克隆限制（用户明确要求，优先于其他建议）

- 第一主服务商选择 MiniMax，密钥通过环境配置读取。当前工作区 `.env` 已有 `MINIMAX_TTS_API_KEY`；本文不记录其值，不复制到前端、日志、测试数据或 Git。
- 用户已有克隆音色，要求复用。用户告知再次声音克隆约需 9.9 元/次，价格以实际账号账单为准；无论价格变化，**本版禁止再次调用声音克隆创建接口**。
- 同样禁止为了查询/测试而上传克隆样本、创建试听克隆、重建音色、删除已有音色或清理远端音色。查不到已有 voice ID 不能自动创建替代。
- 允许读取已有音色清单与登记已有 voice ID；如服务不可达，说明待确认，继续离线开发。
- 允许必要且有上限的真实 TTS 调试，默认先用 FakeTTS/已保存测试音频；不把付费 API 用作每次单测、CI 或浏览器回归的依赖。
- 同一授权音色不可因服务商故障而静默切换。若用户明确选择其他音色，应生成新的音频版本、重新检查和记录选择。

### 1.3 本轮只完成的查询与实际结果

2026-11-05 本轮核对到 main 已合入 V1.0+ 候选源码，提交 `215f262`；工作区无生产 TTS 适配模块，仅有相关测试密钥隔离记录。此为计划编写时基线，开发时重新核对。

确认 `.env` 中 `MINIMAX_TTS_API_KEY` 已设置，只检查配置存在性，没有输出密钥。

访问 MiniMax 官方文档失败；另向候选音色查询地址 `https://api.minimaxi.com/v1/get_voice` 发送一次只读查询尝试，请求类型为已有克隆音色，因网络错误未取得有效响应。统计：音色查询尝试 1 次，TTS 合成请求 0 次，克隆请求 0 次。没有进行自动重试。

因此尚未确认实际 voice ID、音色数量、当前模型及费率；不能将查询失败记为账号无音色。本轮未在线核验接口/字段/价格，下面涉及 MiniMax 具体能力的内容是待 S0 官方核对的要求，不是已验证承诺。

### 1.4 建议的初始调试预算

- S0 在联网条件修复后，先进行最多 1 次新的音色清单读取；避免反复刷新设置页造成重复调用。
- 开发机付费 TTS 冒烟测试建议限制为最多 2 个发送请求，每次不超过约 60 个中文字符，累计约 120 字；按请求发出次数计算，失败/超时不自动返还调试额度。
- 克隆创建、删除和样本上传请求上限永远为 0。
- 上述是短样例调试预算，不是产品正常使用上限。真实 2～5 分钟成品验收另列批次，先估算收费口径和文本量、明确本轮额度，再执行一次代表性生成；后续回归优先复用缓存。
- 没有确认费率时显示“费用待核实”，不能显示为免费或零费用。用户可调整调试预算，开发者不得为解决失败自行无限扩大次数。

## 2. 当前基线、依赖与部署边界

### 2.1 V1.0+ 的复用条件

V2 可以从包含 V1.0+ 的 main 建立独立开发分支并隔离验证。V1.0+ 共用修复按仓库分支规范同步；不能覆盖其固定 run 证据或拿旧候选结果证明 V2 合格。V2 团队部署/发布需同时满足依赖功能和新版本实际环境验收。

既有成员等级为管理员、维护负责人、普通成员；项目 ACL 独立限定操作范围；作者自审按已确认团队策略执行。AI 审稿与人工批准继续分开。

### 2.2 技术路线

- 保留 Vue/FastAPI/SQLite/文件素材库、一个数据根、一个应用实例/ASGI worker。
- 图文原有 `articles`、工作副本、revision 和定稿快照契约保留。其他媒介增加以产物 ID 为边界的记录与版本，不把一篇主题复制成多篇不关联的文章，也不把所有媒介写进唯一图文正文。
- MiniMax 使用独立 TTS 适配器和能力描述；不把 TTS 请求伪装成聊天模型输出。第二服务商只留协议扩展口，本版不要求实际接入。
- 云端 TTS 负责合成，FFmpeg 等本地工具负责探测、重采样、拼接、响度与混音。精确字词对齐工具后续按当前 MiniMax 返回与语料实测选择。
- 任务沿用单实例所有权；TTS 网络并发默认 1，音频后处理使用有界子进程。是否新增实例内任务泳道在 S0 评估，不能直接启动独立 worker 或多个 SQLite 写入实例。
- 家庭部署目标历史确认是 Windows 11 NUC8i5BEH、i5-8259U、约 32GB 内存，优先 Windows 绿色包与独立 runtime。历史磁盘可用空间较紧，S0 重新测量；不假设历史剩余空间仍有效。
- 本版不引入 GPU、本地语音大模型、Redis、微服务或 PostgreSQL 强制迁移。

## 3. 产品产物、编辑与审批规则

### 3.1 一个项目、多种产物

每个主题项目共享素材/证据与人设；可包含图文稿、口播稿、字幕稿、分镜稿和生成音频。产物保存独立稳定 ID、类型、语言、版本/revision、来源关系、状态、编辑者和审核记录。

V2 实际交付图文、口播与音频；字幕文本/时间信息可在增强阶段交付。分镜仅预留产物类型与关联契约，不在本版制造空白视频编辑器或承诺视频渲染。

图文改动不自动覆盖口播稿，口播改动不自动改图文。共享关键事实改变时提示派生产物复核；无法确定精细事实关系时先按源版本保守标记，并允许人工确认不受影响。明确各自依赖，避免循环自动同步。

### 3.2 口播段落与发音文本

口播以稳定段落 ID 为单位，支持编辑、重排、删除、重新生成及来源定位。保存展示文本与最终发送 TTS 的发音文本及转换规则版本，数字、缩写、单位等转换不能只存在于临时内存。

口播创作要求：去除不可朗读的引用标记；缩短长句；将书面结构改为开场、事实、解释和结尾；处理专名、英文缩写、数字和单位；保留事实依据，不将缺失解释写成确定事实。

可选时长作为策划目标，实际时长按返回音频测量。超出 2～5 分钟时优先编辑脚本，不能为凑时长无提示大幅变速或增加无依据内容。

### 3.3 声音档案

管理员登记已有声音：服务商、voice ID、显示名、来源/授权说明、允许使用范围及查询确认时间。账号级音色清单不等于应用全部成员可使用；默认采用显式可用档案/项目范围。

API 密钥只在服务端读取；profile 保存非密钥标识与能力。模型、语言、音色、语速、音高/音量、发音词典、情绪等仅暴露当前服务实际支持并验证的参数；SSML 等能力未确认前不默认支持。

保存默认声音设置与每个音频版本的实际参数快照，刷新、重启或默认档案变更不会悄悄改变旧成品。远端音色不可用时说明原因，不自动重建。

### 3.4 权限与两层审核

有项目创作权限的成员可改口播、选择获准声音、发起草稿合成和试听；项目只读成员可查看获授权产物。管理员管理服务商配置、声音档案和额度；不新增网页任意文件/系统命令能力。

口播稿人工审核绑定稿件快照与事实来源；成品批准绑定口播快照、片段清单、声音参数和混音配置。沿用自审策略及权限，不新增强制第二人审批。

草稿合成用于创作预览，不等于定稿或已审成品。正式音频定稿、成品导出/重试继承维护负责人/管理员的发布能力，普通成员可播放和下载已获授权的既有成品。文件访问包括片段、预览、最终音频和字幕，均查当前项目 ACL。

脚本文字变化使相关片段与成品过期；音色/发音/语速变更使受影响声音片段过期；仅混音、片头片尾或背景音乐变化只重做本地后处理。成品变化须重新确认成品批准；不因此无故撤销未变化脚本的审稿历史。

## 4. 任务、缓存、取消与费用契约

### 4.1 任务分层

计划、合成和后处理分开：口播创作/审阅任务 → 分段 TTS 批次与片段任务 → 拼接/混音任务 → 导出任务。记录发起成员、项目/产物 ID、输入快照、参数、尝试次数、服务商状态、实际时长与费用状态。

进度基于已完成片段、请求/等待、校验、合并和导出阶段显示。服务商未返回内部进度时不能虚构精确完成百分比。

输入变更或成员撤权后重新校验写入；结果可以保留为受授权的历史/候选，但不能覆盖最新稿件或错误推进审批状态。

### 4.2 缓存与增量更新

片段缓存至少考虑：发送文本摘要、服务商/模型、voice ID、规范化参数、语言、发音规则/词典、必要的输出格式和随机参数。模板/规则更新应有版本标识；不使用仅依赖段落序号的缓存。

相同输入可复用已校验片段；修改一个段落只重合成该段；重排和删除可复用其他片段，再重建后续拼接时间。不能因为最终时间轴改变就对全部未变段落重新发 TTS 请求。

缓存命中不产生新 TTS 调用；仍记录缓存命中与本地处理。跨项目缓存复用必须保留授权和归属，不能通过摘要查找暴露其他私有项目的音频或文本。

成品有独立输入清单和校验摘要。更改全局声音等可能让多个片段失效；不得承诺所有操作都只重生成一段。

### 4.3 取消、超时和恢复

- 排队任务取消后不再发送请求；批次取消阻止后续片段和发布替换。
- 请求已发送后，本地取消不保证服务商停算或不收费。标记已发送与取消请求，不把费用自动清零。
- 明确未发出、失败、响应未知、完成待校验、已完成等状态；返回未知时先确认服务端可查状态/请求标识能力。
- 不具备服务商幂等/状态查询时，响应未知不自动重发；人工明确重试会产生新尝试并提示可能重复费用。
- 429/可恢复错误仅按确认的服务语义有限退避；调试模式关闭自动付费重试，永久鉴权/音色错误不重试。
- 重启后重建批次状态，复用完整片段；缺损片段标记待处理，不能把任意已有文件视为成功缓存。
- 临时文件/后处理失败不替换上一个完整成品；最终替换与既有固定导出契约一致，不让旧批次覆盖新成品。

### 4.4 成本与资源控制

同时记录 TTS 请求次数、已发送文本量、缓存命中、失败/未知尝试、生成耗时，以及口播 LLM 创作/审阅成本。本地处理耗时与服务商账单分开。

估算保存服务商/模型费率来源、币种、收费单位和生效时间；字符/字节/token 等按官方当前口径核对。服务商没有真实费用字段时，标记估算/待核对，不宣称已准确对账。

提供批次估算、次数/预算上限和额度不足提示。费用账本通过服务端共享计数控制，不能每个进程/页面刷新重置。并发请求预留额度，超时额度待核对，不自动视为零成本。

限制上传、片段长度、后处理并发、输出时长和磁盘占用；空间不足时拒绝新生成并保留已有版本。历史音频和引用文件不能以“缓存清理”为由直接删除，先制定归档与保留策略。

### S0：基线、MiniMax 能力与既有音色登记方案

**对应**：V2.0 启动，V2.3 既有音色复用前提。

**实现/准备**

- 核对 main/V1.0+ 分支状态、未提交改动、当前依赖与真实验收缺项。
- 核对运行时 `.env`/环境变量优先级，只显示密钥是否设置；开发机与 NUC 密钥配置分别确认。
- 查官方当前 API 的区域域名、鉴权、音色查询、合成端点、模型、输入限制、音频返回、错误、时间信息、计价和已有音色可用条件。
- 在调用上限内查询已有克隆音色，确认用户要复用的 voice ID；多候选时用非敏感名称/标识选择，不为挑选音色批量生成试听。
- 若联网/查询失败，允许管理员后续输入已知 ID，标记未验证；保留待验证项，继续 FakeTTS 实施。
- 重新测量磁盘，核对 FFmpeg/媒体探测工具、Windows 打包可用性及许可/分发方式。
- 完成产物/审核/任务/缓存/权限方案、迁移路线和调试预算。

**验收**

- 基线与 API 核对结果可追溯，voice ID 是已查询确认/用户提供/待确认三者之一，不能虚构。
- 测试隔离真实密钥，克隆请求路径不进入产品或验证工具调用白名单。
- 真实请求次数与失败事实记录完整；网络不可用时不扩大付费调用次数。
- 形成 S1～S9 的实施契约与仍需用户/网络条件的清单。

**预计**：0.5～1 个开发日。

### S1：多媒介产物与版本基础

**对应**：V2.0。

**实现**

- 项目内产物类型、稳定 ID、版本/revision、来源关系与状态；图文继续按原契约工作。
- 口播段落结构、共享事实/素材/人设关联，预留字幕与分镜产物关联。
- 产物级读写、历史、审批和文件授权，复用成员等级与项目 ACL。
- 音频片段、成品、任务和参数快照的存储边界；禁止将未批准成品混成图文定稿。

**验收**

- 一个项目可同时保存图文和口播并独立编辑，重启后关系保留。

- 普通成员/审核者/无权限成员的产物读写与历史访问符合 ACL。
- 升级迁移可重复启动，失败可回退；字幕/分镜预留不是空白功能上线。

### S2：图文转口播与段落编辑

**对应**：V2.0/V2.1。

**实现**

- 项目创作 Brief：目标听众、人设、语言、目标时长和用途。
- 图文转口播策略、来源定位、标题/开场/主体/结尾及规则化可朗读文本。
- 口播段落新增/修改/删除/重排、局部重写、保存与版本冲突处理。
- 发音文本与显示文本分开保存；基础数字、单位、缩写与引用清理。
- 现有 LLM 路由与费用记录复用，不为本阶段重新构建 Agent 继承体系。

**验收**

- 固定新闻样例生成有来源的口播，不朗读 Markdown 引用标记，不改变关键数值或添加无依据事实。
- 数字、百分比、型号、中文/英文术语有明确读法；人工改动发音文本可保存。
- 局部重写只作用目标段落；同一段并发保存冲突保留本地输入。
- 保存、刷新、重启后口播版本与段落 ID 保持一致。

**预计**：2～3 个开发日。

### S3：MiniMax TTS 适配与声音设置

**对应**：V2.1，V2.3 仅复用。

**实现**

- TTS 协议、MiniMax 适配、FakeTTS、能力描述和可配置模型/端点。
- 管理员登记/查询既有声音档案，成员只选择获准音色；保存项目默认与版本参数。
- 请求/响应校验、音频解码、错误分类、最小音频完整性与实际时长探测。
- 支持经核实的语速等基础参数；不支持的设置在界面明确说明，不静默忽略。
- 调试模式次数上限、发送前费用预估、禁止克隆与远端删除的测试护栏。

**验收**

- FakeTTS 完成确定性响应、错误和能力不支持验证，无真实网络依赖。
- 在初始额度内完成必要短文本合成或明确标记网络待验证；记录所用模型/voice ID、请求次数和音频时长。
- 密钥不出现在网页、错误文本、日志、请求 URL 和导出清单。
- 现有克隆音色错误/不可用时不重新克隆、不切换声音；声音设置重启后保留。

**预计**：1.5～2.5 个开发日。

### S4：分段任务、缓存、增量生成与费用账本

**对应**：V2.0/V2.1。

**实现**

- 按段计划、合成、校验、拼接的持久任务批次，实例内有限并发。
- 片段缓存键、费用计数和版本绑定；发起人及写入时授权检查。
- 精确表达排队/已发送/响应未知/成功/失败/取消请求等状态。
- 批次取消、有限重试、服务重启恢复和失败续跑；缓存不包含半文件。
- 片段过期提示、局部生成和全局声音变更影响范围。

**验收**

- 同一输入再次生成不新增 TTS 请求；修改一个段落只新增该段请求，其余片段复用。
- 段落重排/删除只需重拼接；换全局声音正确使受影响片段过期。
- 排队取消不发请求；已发送取消不能虚报零收费或保证服务商停止。
- 网络超时的响应未知任务不会自动重复付费；恢复后任务与费用账本不重置。
- 重启、成员撤权、过期 AI 结果、批次重复点击和后处理失败均不覆盖新版本或完整旧成品。

**预计**：2～3 个开发日。

### S5：音频创作工作台与单人旁白 MVP

**对应**：V2.1。

**实现**

- 创作页图文/口播/音频产物入口，复用素材与审核侧栏；避免额外复制项目工作台。
- 口播段落、声音设置、分段试听、局部重生成、整段音频播放和任务进度。
- 显示过期片段、待处理、调用估算与缓存命中；播放当前预览与历史成品清晰区分。
- 合并片段并统一必要的采样率/声道，保留自然段落停顿；生成可播放预览与标准音频。
- PC 主要编辑；手机至少登录、试听、看状态和简单口播编辑。

**验收**

- 同主题图文和音频并存；可试听单段和整段，修改段落后能辨认哪些内容待更新。
- 跨段无明显突兀断句/音色跳变，音频文件有效且浏览器实际可播放。
- 设置修改/刷新/重启不丢失；过期预览不伪装为最新成品。
- 项目文件访问与播放符合当前 ACL，未授权旧 URL 不能访问。
- 不引入双人对话、RSS 分发、实时变声或音色生成界面。

**预计**：2～3 个开发日。

### S6：口播审核、音频定稿与导出闭环

**对应**：V2.1 完成门槛。

**实现**

- 口播 AI/规则审阅：事实支持、口语表达、读音风险、重复、节奏与时长适配。
- 人工口播提交/意见/批准与成品试听确认，沿用项目审核能力与允许自审策略。
- 成品固定音频清单、版本、参数、来源、审批关联和校验摘要。
- 导出 MP3 等默认可用格式，按实际需求可选 WAV；附口播文本、必要清单与时长，敏感配置不导出。
- 成品安装/替换失败保留上一完整导出，旧批次不能覆盖新导出。

**验收**

- 固定主题完成口播退回/修订/批准、合成试听、成品批准、正式导出。
- 修改口播使相关音频/成品待更新；修改声音/混音使成品待复核，脚本历史不丢。
- 普通成员可在项目权限内创作/审核/试听，定稿与正式导出继续检查发布能力。
- 一次预先预算的真实主题生成 2～5 分钟可用音频；事实、重点读音、停顿、音量和跨段连贯性人工抽查。
- 无法完成付费长样例时，将真实成品验收保留为待验证，不用 FakeTTS 冒充自然度和音色一致性通过。

**预计**：1.5～2.5 个开发日。

### S7：发音、停顿、片头片尾与混音增强

**对应**：V2.2。

**实现**

- 项目/声音适用的发音词典与覆盖规则，保留原词、读法、规则版本及可回退历史。
- 语义分段与停顿控制，有限情绪参数按 MiniMax 当前能力校验，不能未经测试批量展示。
- 片头片尾与背景音乐素材选择，来源/授权提示、裁切/循环和淡入淡出。
- 旁白优先的背景音量压低、响度处理与削波检查；默认响度目标在 S0 按输出用途确定。
- 更改纯混音只执行本地后处理；发音规则或声音参数影响的片段重新合成。

**验收**

- 专名/缩写/数字发音规则可重复复现；修改一条规则只更新使用它的片段，无法精细分析时明确范围。
- 混音、片头片尾或响度变更不新增 TTS 调用，历史成品仍可播放。
- 旁白清晰、无明显削波或不合理接缝；响度报告记录测量方法和目标，不只主观宣称一致。
- 不支持的情绪/停顿语法明确提示；所有背景素材受授权和项目 ACL 约束。

**预计**：1.5～2.5 个开发日。

### S8：字幕/时间映射与产物更新增强

**对应**：V2.0 的下游基础及 V2.2；为 V3 铺垫，不渲染视频。

**实现**

- 保存实际片段起止时间、段落到音频的映射，区分段落时间与精确字词时间。
- 字幕展示文本与发音文本映射；若 MiniMax 提供可信字词时间信息则验证并使用，否则评估强制对齐/ASR 辅助，未实现时只交付段落时间。
- 可选字幕预览与 SRT/VTT 导出，显示对齐质量和手动修正；精确字幕属于真实工具验证后能力。
- 维护图文→口播→片段→合并音频→字幕/成品的单向依赖与更新原因。
- 片头片尾、停顿、变速或混音改变时间轴时重新计算映射。

**验收**

- 重排、删除、插入段落后时间正确更新，未变片段不重新合成。
- 数字/缩写显示与读法映射可查，修改字幕不能无提示改变声音稿。
- 不按字符数均分时长，不将段落时间标记为字词级精确对齐。
- 精确对齐若交付，使用固定语料人工抽查并记录偏差；约 200ms 可作为初始目标，实际误差和工具能力需如实记录。
- 无时间信息或对齐失败时保留段落映射与待验证状态，不阻塞已可用单人音频发布。

**预计**：1～2 个开发日；新对齐工具适配另估，可在 V2.1 后独立交付。

**验收**

## 7. 验收样例与指标

固定语料至少覆盖：普通科技新闻、数字/单位/日期、英文缩写/型号/人名、带引用标记的长文、资料不足或冲突、空文本、超长段落、多段重排、授权撤销和响应未知任务。

质量：事实支持、可听懂程度、重点读音、跨段自然度、实际时长、响度/削波、音色一致性、人工修改量与意见采纳。自然度和读音不能只由 FakeTTS 或 LLM 自评证明。

稳定：缓存命中、每次修改新增的 TTS 请求数、异常/取消/重启行为、任务耗时、峰值内存与磁盘占用。完整生成与局部修改成本分别记录。

经济：费用估算与可取得实际账单分开；归集已发送/未知/失败尝试和缓存，记录每份最终成品总投入，不只计算成功片段。

权限：管理员/维护负责人/普通成员，加上无项目权限身份，验证正文、片段、声音选择、历史、音频文件、任务、费用、审核与导出。

每阶段证据含源码/构建版本、数据根、样例、API 调用账本与验证环境；不记录密钥、Cookie 或完整账号资料。脚本/配置/声音参数变更后的旧结果不得直接继承为通过。

## 9. 新开发对话任务说明

按照 docs/dev-plan-v2.md 分阶段开发文枢 V2 音频创作闭环，先执行 S0，再按 S1～S9 推进。复用已合入 main 的 V1.0+ 候选基础，在独立开发分支隔离实现；遵守当前仓库分支、版本与授权规范，保留既有 V1.0+ run 证据和未提交改动。

MiniMax 是首个 TTS 服务商，密钥在运行环境/.env 中，通过 MINIMAX_TTS_API_KEY 服务端读取，不泄露或写入 Git。用户已有克隆音色，先按预算查询并复用 voice ID；严禁调用新的克隆、样本上传、重建或删除接口。查询失败就保留待确认，不能自动创建。故障不能静默换音色。

先用 FakeTTS 和固定音频完成多数验证，真实调用遵守本计划初始小额调试预算、记录全部尝试，超时响应未知不能自动重复付费。长音频验收先估算并明确批次额度，缓存复用优先。不要把 AI/规则审稿当作人工批准，也不要把 FakeTTS 测试当作音色/自然度的真实验收。

每阶段提交实现范围、证据、数据变化、费用账本、遗留问题和回退方式，再推进下一阶段；分别记录开发机、真实 MiniMax、NUC 和手机/远程验证。V1.0+ 未完成真实门槛继续独立保留。本版不开发视频渲染、双人播客、RSS、新声音克隆或平台自动发布。
