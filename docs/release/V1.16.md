# V1.16 环境热加载、页面同步与启动优化

版本：1.16.0。继续在 main 开发，沿用 V1.15 的 schema v3 与工作版本规则。

## 使用变化

- 设置 → **刷新环境变量（Reload Env）**：保存运行目录的 `.env` 后点击，模型、搜索、媒体密钥与 HTTP 代理对新请求立即生效。无需重启。界面显示成功/失败与服务可用状态，不返回密钥。
- 创作/审稿页：后台创作、复审或 AI 修改完成后自动获取最新内容；正在输入或打开 AI 弹窗时保留本地状态，结束编辑/关闭弹窗后补刷新。旧版本只读查看保持原选择。SSE 重连时补取当前状态。
- 小红书卡片：点击缩略图后，←/→ 或上一张/下一张按钮翻页，首尾不循环，Esc 或点击背景关闭。输入框内方向键保留编辑含义。
- Windows 绿色包改为目录式：`文枢.exe` 与 `_internal/` 必须共同保留，免去每次启动的单文件自解压。浏览器仍在 `playwright-browsers/`，无需用户安装 Python。

## 环境变量语义与边界

启动时保留外部进程环境优先级；用户主动刷新时，`.env` 中的值覆盖当前同名值。删除文件中的键会恢复启动前的进程值，无原值则删除；写空值可显式禁用渠道。支持 UTF-8/BOM、注释、引号、多行值与 `${KEY}`（依次引用本次文件中前面定义的变量或启动前环境）。不执行文件内容。

先解析完整文件，再在共享锁下替换配置；缺失文件、编码错误、无效行或无效字符不会部分应用，不把原文/密钥放入错误信息。正在发送的请求继续完成，后续请求使用新密钥；忙碌 HTTP 连接在释放后关闭，后续请求重建代理连接池。

数据目录、日志目录、CORS、Playwright 浏览器路径、PATH/PYTHONPATH 属于启动绑定配置，发生变化时整个刷新被拒绝并提示重启。远程绑定禁止热刷新清空访问令牌。`APP_ACCESS_TOKEN` 可轮换：本次授权会话重新签名，前端清除旧本机令牌并重连；其他会话需使用新令牌登录。

Docker 的 `--env-file` 注入的是启动环境；要使用页面热加载，需要将可编辑 `.env` 挂载到应用运行根 `/app/.env`。

## 启动链路

性能分析定位：原启动导入链 `main → articles/queue → orchestrator → collector → crawl → trafilatura`，`import app.main` 新进程基线约 2.6 秒（含解释器），其中正文抽取库累计约 0.46 秒。

V1.16 将 Agent 初始化推迟到首个任务，将通用正文提取库推迟到首次抓取。首次外部项目全量扫描改到后台，保留 DB 初始化、单实例锁、任务恢复后才设置就绪；扫描线程随最后一个应用生命周期结束，错误写日志。日志记录 lifespan 到就绪时间。

使用 `scripts/profile_startup.py` 可在独立临时数据目录复测进程启动到 `/api/ready` 与 SPA HTML 返回。此指标不等同于浏览器绘制完成，也不等同于重启操作系统后的磁盘冷缓存。首次任务可能承担延迟导入费用。

## 验证记录

已通过 97 项后端回归与 5 项真实浏览器流程，Vue 构建、Windows exe 四平台及独立安装 wheel 验收通过。详细交付清单见 [ARTIFACTS.md](ARTIFACTS.md)。平台业务、工作版本/定稿/历史回滚及固定 exports 目录规则沿用 [V1.15](V1.15.md)，本轮无需新数据库迁移。

同机三次新进程测量中位数：源码 `/ready` 1.911 → 1.462 秒（约 24%），Windows exe 17.333 → 1.478 秒（约 91%）。新版 exe 范围 1.475–3.409 秒；操作系统文件缓存未清除，不能等同于磁盘冷缓存启动。首次任务可能增加约正文提取库导入的耗时；没有提前执行模型调用或浏览器预热。原始样本见 [V1.16-startup.json](V1.16-startup.json)。
