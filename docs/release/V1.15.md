# V1.15 Bug 修复与发布内容说明（2026-10-29）

## 版本与审稿

旧实现每次修复均增加版本，内容 hash 随之变化；下一条审稿意见仍绑定修复前的 hash，因而被判过期。
现在未定稿文稿使用持久工作副本：连续编辑、重写、采纳修复均保持当前版本号，只递增内部 edit_revision。
定稿封存当前版本，之后首次修改自动创建下一版，创作/审稿视图读取最新版本。SQLite 保存未定稿状态，刷新、重启可继续。

审稿结果生成结束时校验它实际读取的版本及 revision；迟到结果不能更新生命周期或成为有效意见。
同一有效工作版本的意见可连续处理，跨版本和已删除段落仍拒绝。内容变化后界面提示建议复审，
这不表示新增正文已经接受 AI 事实核验。定稿重新检查当前正文的排版/禁用词规则，未处理 blocker 仍阻止普通定稿。
强制定稿保留原因；并发冲突必须刷新，不能强制覆盖。

回滚把历史定稿内容恢复到工作副本，覆盖尚未定稿改动。定稿前回滚保持当前号，定稿后首次回滚开下一号。
旧增量历史继续可读，已定稿快照不被覆盖。旧“保存版本”API 兼容为保存工作备注，正式版本节点由定稿建立。

## 路径与导出

原代码已创建部分目录，但冻结素材、卡片渲染和后续文件操作使用位于项目目录内的旧路径；
项目标题改名可能使这些路径失效。新实现将生成阶段移到稳定的 `<data_root>/.export-staging/`，
安装阶段在目录锁内重新读取当前项目路径、校验归属并自动创建父目录。
新增故障回归覆盖生成期间项目改名，以及模拟路径缺失、替换失败恢复上一份文件。
原始用户异常的完整 traceback 未提供，因此不将这些已验证的失效路径等同于唯一现场根因。
导出失败现在记录平台、文章和完整堆栈，并向界面返回路径/素材的具体提示。

最终文件固定写入 `resource/<项目目录>/exports/<平台>/`。重新生成成功才替换整个平台包；
失败保留上一份完整包，任务失败提示与可下载文件分别展示。没有新 runs 目录或文稿 snapshot.json。
manifest.json 仅记录文件清单、校验和及来源版本信息；导出不管理文稿历史。
旧 runs 保留，在尚未生成固定平台包时兼容展示旧成功包。不要直接删除已有用户目录。
生成卡片也更新同一小红书包，不再单独保留尾页，Logo 和 slogan 位于最后一页文案底部；图片末页同样预留品牌区。

## X（Twitter）内容结构

“正文文件 + 媒体文件”适合人工发布，但旧 thread.txt 缺少每条长度及媒体对应关系。
现在输出 post-01.txt、post-02.txt 等可直接复制的单条正文，thread.txt 为合并预览，thread.json 指定回复顺序及媒体。
发布第一条后，下一条回复上一条；预览中的 `---` 不属于正文。

普通帖文采用 280 加权字符规则：中文通常按 2 计算，URL 经 t.co 按 23，文本先做 NFC 归一化。
序号、来源和签名全部纳入预算，URL 不拆断。实现对复杂 emoji 采用保守上界，可能比官方计数提前分条，
最终以平台编辑器或官方 twitter-text 校验为准。最大条数是软件配置目标，超出时 thread.json 与 README 会明确提示截断，
可提高设置或人工追加。没有默认启用账号专属长帖能力。

每条按最多 4 张静态图片，或 1 个 GIF，或 1 个视频选择，不推荐混用；当前首条附媒体，其余条可人工补充。
媒体清单精确列出应上传的文件，上传大小、时长、格式仍需在实际账号编辑器检查。

已核对的官方来源：

- [X 字符计数](https://docs.x.com/fundamentals/counting-characters)
- [X 创建帖文及媒体约束](https://docs.x.com/x-api/posts/create-post)
- [X 帖文及回复结构](https://docs.x.com/x-api/posts/manage-tweets/introduction)

## 微博内容结构

手动发布包包含 weibo.txt（摘要 + 完整话题 + 签名）、media.json（应上传的媒体及文字长度）和 media/。
默认 140 是本软件的保守摘要目标，已把话题与签名计入，不能解释为所有微博账号、网页/App、长文功能的统一硬限制。
普通图文采用保守的最多 9 张静态图模板，或单个 GIF/视频；账号支持更多图、长微博或头条文章时可人工选择对应编辑模式，
本轮没有实现这些模式或自动上传接口。

微博开放平台旧 upload/share 文档写有 140 汉字及单图片约束；share 还限制话题和绑定域 URL。
这些是具体 API 的契约，不应套用为手动发布的统一规范。未来接入 API 时，应独立实现对应接口和应用权限的适配，
不能把当前带话题的手动发布包直接当作 share API 参数。

- [微博 statuses/share API](https://open.weibo.com/wiki/2/statuses/share)
- [微博 statuses/upload API](https://open.weibo.com/wiki/2/statuses/upload)

## 升级与功能影响

采集、素材导入、AI 模型路由及四平台人工发布保留；变化集中在版本触发时机、导出目录和内容布局。
未定稿工作副本是数据库内容，不会每次编辑落盘为正式 vNNN.json；拷贝项目目录不能代替数据库备份。
升级前停机并做完整离线备份；schema v3 首次迁移前另存数据库备份 before-schema-v3.sqlite3。
回退旧程序须恢复完整旧备份，不应使用新库运行旧程序。旧 exe 必须替换新构建，包状态见 ARTIFACTS.md。

本轮实际验收还发现冻结 Python 对输出管道选择 cp1252，导致中文 --version 失败；冻结入口已显式配置 UTF-8。重打包后的 --version、--build-info、空数据根启动和四平台实际生成均已通过。
