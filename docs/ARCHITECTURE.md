# 架构优化与升级说明（1.11.0）

本次保留 FastAPI + Vue + SQLite 的模块化单体、Block/DraftDoc 和四平台手动发布。
主要目标是将数据一致性、运行所有权和部署验证变成可执行约束。

## 应用边界与不变量

- 文稿服务负责短事务、版本 CAS、增量日志与 checkpoint；纯分页算法位于 core。
  API 提交的是它实际读取的版本，旧 ID 返回 409，虚构版本返回 404。
  AI 调用在事务外运行，提交时再次检测 HEAD，避免迟到结果覆盖人工编辑。
- `workflow` 负责定稿：审稿内容 hash 必须匹配当前稿。完整审稿、无模型的规则审稿、
  AI 审稿失败明确区分。规则审稿仍允许人工定稿；强制跳过缺失/过期/失败审稿或 blocker 会记录原因。
  定稿本身生成新 checkpoint，内容 hash 不随存储版本变化。
- 每次实际内容修改及回滚统一处理 EDITING 状态，包含 AI 修复、资料融合和 DONE 后继续编辑。
  迟到审稿保留报告，不推进新内容或已定稿内容的生命周期。
- 数据库是权威来源，checkpoint 文件是可重建投影，文件写入失败会记录日志。
  读版本与时间线使用一致性读快照；版本组和状态变化一起提交，失败不留下半个版本。
- 新目录带文章 ID，文件名带内容摘要；跨库复制保留来源关系。
  删除采用归档，素材行、原文件及历史引用保留，活动检索不再返回它。
  重抓生成新素材，已有引用继续对应旧来源；向量缓存按模型/内容标识更新，FTS 与向量使用相同文章范围。
- 导出入队绑定定稿 ID、素材清单和配置快照，文本与卡片使用同一文稿。
  输出位于 `exports/runs/<job-id>/<platform>/`，平台文件先在私有 staging 完成，再原子安装。
  `snapshot.json` 与 `manifest.json` 记录版本和文件 hash；同任务恢复会校验并复用完整输出。
  SUCCESS、PARTIAL_FAILED、FAILED 分开报告，失败不会撤销文稿定稿，重试只处理失败平台并使用原快照。
  后续成功或执行中的平台任务会覆盖旧失败记录；重复点击单平台重试返回同一在途任务。

## 运行与可观测性

`create_app` 只组装应用，lifespan 管理初始化、AppContext 和 WorkerRuntime。
每个数据根使用操作系统文件锁，生产部署必须使用 **一个 ASGI worker**。
同一进程的同根应用借用一个 runtime 并引用计数，创建第二个 factory 不会恢复活跃任务。
跨进程持锁期间不能恢复或认领同一任务库。崩溃由 OS 释放锁后才恢复 running 任务。

SQLite 连接显式关闭；HTTP 客户端按来源/代理有界复用，保留 Windows PAC、环境代理及 NO_PROXY。
重试次数有限，永久输入错误不自动重试，可恢复失败采用退避。创建和导出的已完成副作用可在同任务恢复时复用。
停止会等待 worker，长任务超过关闭期限时保留所有权并记录日志，直到任务结束或进程退出。
当前不宣称强制取消任意第三方下载/模型调用或所有副作用的 exactly-once。

`/api/health` 为轻量存活检查；`/api/ready` 检查 DB、worker、队列、磁盘及事件丢弃。
日志包含 request_id、job_id、article_id、stage 与 attempt。事件只用于刷新，数据库查询负责恢复权威状态。
前端按文章合并更新，进度文字不触发全部面板读取，列表采用 SQL 分页；在输入和保存冲突时保留本地缓冲。

## 安全与部署契约

生产爬虫不注册 FixtureCrawler。抓取仅接收 HTTP/HTTPS，检查 DNS、私网地址、逐跳重定向与下载大小。
yt-dlp 的每次显式 URL 请求也做地址检查，但第三方 extractor/代理端解析仍需要出口防火墙约束；
此版本不把 DNS 检查当成互联网多租户环境下完整的 SSRF 隔离。管理员配置的本地模型端点属于可信配置边界。

`/files` 仅提供已登记素材、完成的发布包与限定卡片；数据库、锁、内部快照和 staging 不公开。
主动内容文件使用附件响应和 sandbox CSP。API 使用 Authorization；SSE/媒体通过 HttpOnly、SameSite 会话访问，
访问令牌不再放进 URL。远程绑定必须配置 `APP_ACCESS_TOKEN`，对外部署应由反向代理提供 HTTPS。
开发 CORS 默认限定 localhost/127.0.0.1:5173，其他 Origin 通过 `WENSHU_CORS_ORIGINS` 显式配置。

设置 API 只接收有类型、范围和关系校验的动态项。数据根在进程初始化时固定，路径、模型渠道、hooks
需停机编辑配置后重启。密钥仍由环境变量/.env 注入；日志根可用 `WENSHU_LOG_DIR` 配置。
Docker 分阶段构建前端、隔离构建上下文、按依赖 hash 安装、以 UID 10001 运行。

## 升级、备份与回退

1. 停止旧服务。用 `python scripts/backup_data.py <全新外部目录>` 备份 DB 和文件；
   同根 worker 仍运行时备份会拒绝。不要只复制 WAL 数据库主文件。
2. 安装依赖锁、构建前端、启动新服务。首次旧库迁移前会自动保存
   `backups/before-schema-v2.sqlite3`，并登记 `schema_migrations`；自动备份只覆盖数据库，不能替代完整离线备份。
3. 检查 `/api/ready`，验证一篇历史版本、共享素材、定稿及导出。旧增量日志仍能重放；旧审稿需重新运行。
   已碰撞的历史共享项目目录不自动拆分或改名，因为归属信息可能已丢失；新建项目不会继续碰撞。
4. 回退时停止服务，将完整备份恢复到数据根并使用旧版本。不要在同一个数据根并行运行新旧服务。
   升级后的新编辑须先导出/保存，恢复旧备份会失去备份之后的写入。

归档保留与独立发布快照会增加磁盘用量；暂不自动删除历史文件。物理回收需在离线审计所有历史引用后实施。
源码修改需重启；旧绿色 exe 不会自动获得新代码。`--version`/`--build-info` 可检查新构建。

## 验证和后续演进条件

本仓库提供版本并发与故障注入、迟到审稿、模型能力与缓存、资产归档、导出恢复、权限和网络策略回归；
真实浏览器覆盖输入保护、版本冲突、人工定稿及发布包下载。CI 覆盖 Windows/Linux、Python 3.10/3.12、
Vue 类型检查、浏览器、冷安装 wheel、Docker。只有缺少 Chromium 时卡片测试可以跳过，真实渲染错误必须失败。

依赖更新使用 `uv pip compile pyproject.toml --python-version 3.10 --universal --generate-hashes -o requirements.lock`，
开发锁加 `--extra dev`；更新后须验证冷环境。源码安装按 `requirements-dev.lock` 运行测试，前端要求 Node ≥20.19。
冻结构建锁 `requirements-build.lock` 加 `--extra dev --extra packaging`；发布工具、Linux 构建和 CI 使用同一份构建依赖。
最低 Python 版本必须显式指定，锁文件用环境标记选择各 Python 版本兼容的 NumPy、Pillow 等依赖。

进程配置与事件总线目前仍是单数据根资源，AppContext 显式持有它们。完整独立数据根、多用户、独立 worker
或微服务属于下一阶段业务需求：需要独立租约/权限模型和实例隔离后才能取消单进程约束。
插件 registry 和既有协议继续作为新模型/渠道/平台入口；全量移动目录、引入 Redis 或 PostgreSQL 当前没有容量依据。

仍需按真实负载评估长增量链、100/1000 篇文章和大规模素材检索；本轮没有宣称完成容量压测。
现有 API 与 Agent 的少量直接依赖保留，后续按用例逐步迁移到应用端口，并以依赖规则约束新模块。
