## Windows / Python 或执行包

1. 获取候选构建并校验SHA256；Python路线使用独立环境安装wheel，执行包路线解压新目录，旧程序留存。
2. 创建持久目录（例如 `C:\Wenshu\runtime`）和另一备份目录。复制 `packaging/deployment/team.env.example` 到持久目录 `.env`，保留 `WENSHU_TEAM_MODE=1`；不要把密钥放入Git。
3. 停服务执行 `python -m app --runtime-dir C:\Wenshu\runtime --init-admin admin`，交互输入密码。执行包使用同样参数。
4. 执行 `python -m app --runtime-dir C:\Wenshu\runtime --host 127.0.0.1 --port 8000 --no-browser`，管理员创建成员，成员首次登录改密。
5. 本机完整验证后，按S1手册运行 `register_windows_task.ps1` 注册已有用户的启动任务。实际系统未验证前不可承诺开机恢复；检查用户S4U网络能力和休眠策略。
6. 卡片功能需Chromium；在可联网环境安装/构建后随包提供，或按既有 `--install-browser` 流程安装。公司网络限制需记录，不从不明镜像安装。

## 已有 Linux / Docker

systemd使用已有独立用户与 `wenshu.service` 模板；路径/用户须替换，先安装wheel到独立环境。模板设置一个进程与团队模式。
Docker镜像在开发/构建环境构建、`docker save` 转移、主机 `docker load`；compose默认loopback映射与独立runtime。
执行 `docker compose --project-directory <部署目录> -f <compose模板> up -d` 前先准备runtime/.env和目录权限。
NUC有Docker CLI28.1.1，但复验时守护进程未运行，Compose/Linux/Nginx仍未实际验证；Windows目标路线不要求它们。SQLite和素材禁止网盘同步运行，不启动多ASGI worker。

## 私有跨网络访问与手机

候选先验证私有组网；公网IPv4不是必要条件。可评估Tailscale等现成方案，但须实际确认国内连接质量、公司/商业使用条款及移动端支持，不能预设免费或稳定。

1. 家庭主机、管理员设备、成员电脑/手机从所选方案官方入口安装客户端，记录版本与授权条款。
2. 创建团队组网、邀请三个成员，配置网络ACL仅允许访问文枢端口；系统/SSH管理单独限制维护负责人。
3. 保持应用监听loopback，优先用所选方案的私有HTTPS代理（如经当前版本文档确认的 `tailscale serve --bg http://127.0.0.1:8000`）；核对其可访问范围，不启用公网Funnel。
4. 如使用独立Nginx，替换 `nginx-team.conf` 的域名和证书并在主机执行 `nginx -t`；证书必须被成员手机信任。代理传递Cookie、CSRF/project revision、Host与HTTPS协议，禁用SSE缓存；绝不直接映射resource/、数据库、备份或config/。
5. 手机安装组网客户端并连接后用浏览器打开同一HTTPS入口。完成登录、图片预览、工作列表、退回/批准。通过手机蜂窝和外地网络分别记录成功/失败、首次加载、图片/下载时间与SSE重连。
6. 若客户端不适合成员，重新评估受身份保护通道；有公网条件时可用HTTPS入口，但应用账号/项目授权始终保留。第三方组网账号不等于文枢成员身份。

## 备份、恢复与升级

每日维护窗口：告知成员停止新操作，管理员确认队列已结束/可恢复，再停服务。外部请求重跑可能额外计费。
执行S1离线 `--backup <全新目录>`；Windows任务可使用更新后的 `backup_windows_task.ps1 -ExecutablePath <文枢.exe> -RuntimeDirectory <runtime> -BackupDirectory <全新目录>`，Python路线使用 `-PythonPath <python>`。脚本等待任务停止、执行离线备份并恢复原先运行的任务，但不能代替维护前确认队列；旧候选内置模板不会自动获得新增参数，应使用当前仓库脚本。

针对当前NUC的采集命令、任务实际运行/重启、维护恢复、容量与手机外地验收完成条件见[NUC后续复验](NUC-validation-followup-2026-10-31.md)。
完整备份包含DB、素材、历史定稿/导出、成员/ACL/人工历史、配置/.env，带哈希清单。权限仅主机维护者，密钥备份受同等限制。
本地备份是当前已确认策略；另一设备/异地副本尚未落实，主机或磁盘损坏仍可能全部丢失。不得将本地副本称完整容灾。

恢复：停应用，`python -m app --runtime-dir <全新恢复目录> --restore <备份目录>`，再用明确 `--data-dir <新目录>/resource --log-dir <新目录>/log` 启动。
核对管理员/成员登录、项目权限、评论/批准、旧定稿、图片和导出；确认后再切流量，保留唯一原件。

数据损失24小时、人工介入恢复60分钟是待实测目标；须记录备份量、完成时间、恢复步骤，不能用小型测试替代真实RTO。

## 管理恢复与故障

主机权限持有人先停止服务，再执行 `python -m app --runtime-dir <目录> --recover-admin <已有登录名>`，交互重置密码。
该命令获取同一OS数据根锁，拒绝运行中操作；启用管理员、撤销旧会话、强制下次改密并留痕，没有远程同等接口。
磁盘不足：ready显示503、health仍可达；停新任务，检查log/备份占用，再核对恢复。避免直接删除素材或DB/WAL。
模型失败：查看项目任务/费用，管理员检查渠道；账号401重新登录，权限404核对项目授权，409保留本地修改后核对新版本，428先读取项目。
服务退出：检查进程/任务日志、数据根锁与启动任务，不强制移除正在持有的锁。备份失败不计作完成，先检查清单和空间。
