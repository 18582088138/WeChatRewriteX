# V1.0+ 团队候选版使用说明

软件版本1.1.0-rc.1；正式版仍为v1.0。源码/本地验证完成不等于家中主机及外地成员最终验收。
管理员先按S6维护手册启用团队模式并初始化；每个人使用自己的登录名，首次/重置后更改密码。
手机使用同一受保护HTTPS入口；手机尺寸浏览器验证不能代替实际手机网络验收。

## 三档成员与项目授权

- 管理员：创建/禁用/重置成员，设置模型与系统、查看团队审计、接管所有项目，配置公共素材共享和自审开关；定稿例外必须注明原因。
- 维护负责人：在授权项目内创作/审核，具备创作授权时可以定稿、生成/重试发布包；不能读取系统密钥或添加成员。
- 普通成员：在授权项目内创作、审核和自审，下载既有发布包；不能定稿或生成发布包。

每个项目有一位可用负责人，可分配创作、审核，两项都不勾选即只读。成员等级不会自动开放全部项目。
负责人负责授权、转移和归档；禁用负责人前必须先转移项目。归档保留历史与文件，恢复编辑先解除归档。
新增项目默认归创建者私有。旧项目初始归管理员私有，旧公共库需管理员显式确认共享。
公共素材可复制到授权项目，保留来源并生成独立文件；撤销公共共享不删除已复制的项目副本。

## 创作与人工审核

1. 新建主题，上传/收集素材，选择材料并创作；保存保留原工作版本与revision检查。
2. AI/规则审稿提供质量意见，独立于人工审批。关闭页面不会停止已接收的后台任务。
3. 在“人工审核”选择具备审核权限的成员，提交当前固定快照。审核者从“我的工作”打开待审，核对快照和意见位置。
4. 审核者添加段落/图片/元信息意见，批准或注明原因退回。创作者标记意见已解决或注明不采纳，修订后重新提交。
5. 自审默认允许，也需显式确认此快照。批准前内容已改，服务端拒绝旧快照；重新提交后原批准不代替新一轮审核。
6. 维护负责人/管理员在人工审核页定稿，核验当前批准与AI/规则政策；显式跳过AI阻断会留痕，管理员人工例外须具体原因。
7. 在发布页生成四平台发布包。普通成员查看/下载既有包，由维护人员在平台手动发布，没有自动发布功能。

标题、正文、图片、引用及素材元信息变更会使批准过期；意见处理状态本身不改变批准。
定稿快照与人工决定关联，后续编辑打开新工作版本；已排队导出使用当时冻结内容和素材元信息。
旧定稿/旧导出可读；旧定稿新增导出前必须有人工记录，管理员可用例外原因确认原定稿。

## 冲突、占用、任务与恢复

另一成员已保存时显示409冲突，保留本地输入。先复制/保留修改，查看最新内容，核对后重做保存；不要自动覆盖。
项目revision覆盖素材、任务准入等写操作；文稿同时检查edit_revision，AI迟到不能覆盖人工更新。
“协作记录”中可提示正在编辑；60秒断联到期，20秒续约，它不禁止别人编辑，不替代保存检查。
“我的工作”显示待审、退回和授权项目失败任务；任务记录发起人、耗时、失败原因，费用沿用授权项目的原统计。
退出、禁用、撤权后新请求失败，SSE停止交付未授权更新；已下载/已看到的内容不能从成员设备撤回，已接受的文件传输可能完成。
旧未确认责任任务由管理员显式接管再执行，外部请求重跑可能计费。完整备份/恢复与本机管理员恢复见S6手册。

验收时使用各阶段分支和验收文档，最后再核验整合版本；main未合并，家中主机与外地试运行仍是必做的验收项。
