## 5. 为什么没有“全面测试”

本轮是阶段复验和候选整合验证，不是对所有功能、角色、设备和故障组合做穷举。未覆盖项有两类，原因和处理方式不同。

### 5.1 可以在开发机继续补测，但本轮未完整展开

这些不是必须等待小主机的项目，后续 Agent 应优先补自动化和本地实证：

1. **角色、项目授权与 API 的完整组合矩阵**：现有测试覆盖代表性越权和关键业务入口，但没有逐一穷举每个 API、每种团队角色、项目能力、归档状态及会话状态的组合。应补参数化直接 API 测试，不能只检查按钮隐藏。
2. **团队前端完整点击路径**：现有团队浏览器只有 3 个场景，尚未逐项覆盖成员管理、项目转移/归档、公共素材复制、自审开关、管理员例外、工作列表筛选及所有错误恢复界面。
3. **更丰富的升级固定集**：实际 v1.0 升级回退已跑通，但样本较简单；还应加入归档素材、跨项目同摘要文件、多个历史定稿、旧导出、旧 AI 审稿、pending/running 任务和异常中断迁移。
4. **故障与容量边界**：20 个模拟项目和并行 GET 不是容量承诺。尚未系统覆盖大素材、长任务、队列积压、磁盘压力、SSE 断线风暴、大图/长文和连续多轮编辑的性能与资源峰值。
5. **依赖与安装环境**：wheel 验证继承了 Conda 运行依赖，不等于无缓存、全新依赖解析；构建仍提示缺少依赖锁文件，不能宣称完全可复现构建。
6. **本机容器/代理运行**：Docker 守护进程未启动，Nginx 未配置，因此本机只做了模板解析。可以在开发机补跑 Compose/Nginx，但结果仍属于等价环境，不是小主机部署。

### 5.2 必须获得真实条件后才能验收

1. **真实主机运行条件**：第8节已确认目标NUC的系统、硬件与磁盘，本机安装和任务注册可以继续；正式服务、管理员执行条件、开机/异常恢复及真实持续资源负载仍需实际验证，不能继续以缺另一台机器为前置。
2. **跨网络与 HTTPS**：家庭上行、路由器、公网 IP/CGNAT、私有组网和证书条件未定，不能模拟出中国大陆跨城市连接质量。
3. **真实手机和外地成员**：浏览器视口及本机多 Context 不能替代手机浏览器、蜂窝网络、外地成员设备和人的操作验收。
4. **真实数据与模型**：自动测试刻意屏蔽真实密钥并使用固定素材/降级路线，以避免污染真实数据和产生不可控外部费用；因此没有证明真实模型质量、第三方服务稳定性和真实主题表现。
5. **容灾与试运行**：另一设备/异地副本、真实数据量、维护窗口和 3～7 天使用尚未具备，不能测得 RPO≤24h、人工介入后约 60 分钟恢复或长期稳定性。

这些项目保持“未执行/未验收”，是为了不把代码完成、CI、模拟设备或本机小样本误报为真实环境通过，而不是已经将对应功能判定为失败。

## 6. 后续 Agent 补测与修改建议

### P0：扩大试用前必须完成

- 将第 5.1 节的角色/API 矩阵、团队浏览器路径和丰富升级固定集补成可重复自动化；发现越权、静默覆盖、审批错绑、定稿修改或历史引用损坏时立即停止扩大试用。
- 真实数据升级前，在隔离副本上演练完整备份、schema 迁移、历史/素材/导出核对和旧程序回退，不操作唯一原件。
- 在已确认NUC上完成真实部署，再落实另一独立网络、手机和至少一名外地成员的完整协作验收，之后判断S6/M4。

### P1：真实试运行前完善

- 增加故障/容量测试并分别记录 API、本机渲染、网络传输和外部模型等待，不能用单一耗时掩盖瓶颈。
- 在可用开发机补跑 Compose/Nginx、冷依赖安装和更大迁移固定集；处理实际发现的问题，而非仅增加测试数量。
- 评估依赖锁定和可复现构建；PyInstaller 的可选依赖/隐藏模块警告虽未被本轮冷流程触发，仍应保留观察。
