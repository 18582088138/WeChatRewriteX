# NUC逐项实验与验收标准

本文件和cases.json共同固定验收标准。使用[入口](START-HERE.md)的run与证据流程；本次只交付实验要求，不预判NUC实测通过。示例路径、账号和时段以B01实际核对为准。

通用规则：部分通过仍为整项failed/blocked；每项证据按[模板](EVIDENCE-TEMPLATE.md)覆盖观察、数据、回退及未覆盖范围。历史自动化结果可说明背景，不能替代本项真正的主机/人员/网络实验。性能目标是初始试用门槛，需记录实际基线，不能仅凭样本达标宣称容量上限。

## B01 机器、权限和运行路径

- 执行：核对NUC型号、当前系统、CPU、内存、磁盘空闲、已有用户/服务/原runtime和真实数据；采集`windows_deployment_probe.ps1`，另记录`python --version`、`node --version`、实际Conda环境、PowerShell版本、管理员执行条件。核对现有任务与端口，不覆盖未知任务。
- 通过：确认就是目标NUC；原数据与目标程序/runtime/backup/report目录定位明确；具有当前阶段必要读写/服务注册执行条件；试用预留空间≥8GB。现有服务/初始管理员是否已有已查明。权限或路径未落实时blocked，不把缺权限称硬件不足。
- 证据：当日主机probe、Git HEAD/跟踪改动清单的去敏摘要、路径与实际权限观察。CPU瞬时值不是峰值，32.1GB是历史空闲量而非必须匹配的常数。
- 回退：此项只读；不输出.env、凭据、MAC/公网地址或无关个人文件。

## B02 程序和构建来源

- 执行：对实际使用的ZIP/wheel检查其SHA256SUMS与zip完整性，运行实际exe的`--version`/`--build-info`。记录候选文件名、字节数、SHA、内嵌build commit/source_hash与run固定repo commit。
- 通过：文件未损坏、版本为目标1.1.0-rc.1/schema6路线、程序来源可追溯；核对内嵌build commit到run source_commit的业务源码差异。应用/前端/配置发生变更就重新构建和测试，不让旧exe代表新功能。仅后续验收文档/外置工具改动允许保持旧exe，但明确使用当前仓库运维脚本。
- 证据：校验结果及build-info；`git diff --name-only <build_commit> <source_commit> -- app web/src config pyproject.toml .env.example`的实际输出与差异判断。不同机器的独立构建SHA不必相同。
- 回退：旧程序/包保留；不移动既有候选或正式标签。

## L01 隔离自动化与关键权限

- 执行：使用run-local的build与backend，读取真实日志/XML；补查3档成员×项目授权/负责人×归档、匿名/改密/禁用会话、CSRF、文件/任务/历史、管理员密钥边界。现有`test_role_project_and_archive_http_matrix`覆盖36组合和13类代表请求，不代表每个端点全穷举。
- 通过：类型/生产构建和本次收集的后端测试通过；关键权限、审批、并发与部署测试没有失败/跳过，跳过项必须逐项解释。未获授权请求被拒绝且不改数据；普通成员不能定稿/生成发布包，维护人员只在授权项目内发布。
- 证据：当次实际收集/通过/失败/跳过数量、XML、运行器JSON、角色与端点覆盖清单。不要把历史120与本轮测试相加。
- 回退：仅fixture数据；不在生产shell环境直接运行未隔离pytest。新增缺陷修复后使用新commit/new run重验。

- 通过：真实原件未被试验覆盖；副本保留同一批文章/版本/素材/归档/导出，schema符合实际目标，迁移后旧项目权限保守，旧定稿新导出遵守人工门槛；完整备份恢复和匹配旧程序读取可复查。若没有真实旧数据，须有维护者确认的库存事实及合成升级回退，范围注明“新安装、没有真实迁移对象”，不能编造真实迁移。
- 证据：schema、对象/文件数量与去敏哈希比较、备份大小/耗时、迁移与旧程序回退结果、当前原服务状态。包含真实内容的原备份不提交Git。
- 回退：先另存升级后新增内容，恢复完整备份到全新目录，显式runtime/data/log；不能只切Git或用v1.0读取schema6。

## D02 正式独立实例与三档真实账号

- 执行：按S6维护手册建立绿色包+独立runtime；已有配置/账号先核对，初始化仅在尚无管理员时。三档实际成员首次改密，在acceptance前缀测试项目中完成素材→创作→人工退回→修订→批准→维护人员定稿→四平台导出。额外无权成员用可清理的测试账号，不访问真实私有内容。
- 通过：已认证维护账号ready=200；三档权限符合规则，个人账号不等于共享令牌；普通成员可创作/审核/自审但不能定稿/新增导出。批准后改稿必须重新审核，管理员例外有原因/审计，AI审稿与人工批准分别显示；四平台文件可读且匹配已批准快照。两人同时保存出现409时本地内容保留。
- 证据：账号等级别名、项目能力、实际版本/revision、人工状态/定稿关联、四平台文件/manifest及无权文件拒绝结果；不分享Cookie或真实正文。
- 回退：记录并恢复临时改动的系统自审开关；测试账号转移其项目后停用，测试项目归档。不要删除真实账号/文稿或覆盖唯一数据。

## D03 Windows任务和权限

- 执行：先停止同目录手动实例；在已具备权限的NUC使用当前仓库register_windows_task.ps1。已有同名任务先查身份/路径，不自动覆盖。启动后采集probe及已认证ready，核对仅一个数据根所有者、日志落到指定目录。
- 通过：S4U/有限权限既有用户能读程序/配置、写runtime；任务Running、health可达、成员登录/ready及一次导出成功，服务监听loopback并使用目标数据。0x41301/267009表示正在运行，不仅因非0判失败。
- 证据：任务状态/动作路径/登录类型、时间、服务日志摘要、权限失败或成功的实际观察。不提交任务中的私有Windows凭据。
- 回退：停止并确认属于本实例的任务；保留runtime和原程序。若实际S4U/EFS/权限不适用，保留错误并选择受用户授权的既有系统路线，不能谎称开机已验证。

## D04 注销后持续运行

- 执行：维护者确认注销窗口。可由另一设备观察受保护入口；若尚无外部通道，在NUC安排S4U一次性只读probe于注销之后执行，避免依赖会被注销终止的交互终端。以下示例在管理员PowerShell从仓库根准备（已有同名探针任务拒绝覆盖）：

```powershell
$wenshuProbeName='Wenshu-Acceptance-Logout-Probe'
if (Get-ScheduledTask -TaskName $wenshuProbeName -ErrorAction SilentlyContinue) { throw '先核对已有探针任务' }
$wenshuProbeScript=(Resolve-Path '.\scripts\windows_deployment_probe.ps1').Path
$wenshuProbeArgs='-NoProfile -ExecutionPolicy Bypass -File "{0}" -RuntimeDirectory "C:\Wenshu\runtime" -OutputFile "C:\Wenshu\reports\after-logoff.json"' -f $wenshuProbeScript
$wenshuProbeAction=New-ScheduledTaskAction -Execute "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" -Argument $wenshuProbeArgs
$wenshuProbeTrigger=New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(3)
$wenshuProbePrincipal=New-ScheduledTaskPrincipal -UserId ([System.Security.Principal.WindowsIdentity]::GetCurrent().Name) -LogonType S4U -RunLevel Limited
Register-ScheduledTask -TaskName $wenshuProbeName -Action $wenshuProbeAction -Trigger $wenshuProbeTrigger -Principal $wenshuProbePrincipal
```

- 通过：维护者实际确认注销时间，probe/另一设备观察时间处于注销后、重新登录前；此时应用任务仍Running、health可达。重新登录后确认成员/数据和业务仍一致。仅锁屏或关闭浏览器不算注销。
- 证据：人工确认的注销/再登录时间、期间probe或独立设备记录、之后业务观察。文件存在本身不能证明注销发生。无法安排真实注销时blocked，继续D06/P项。
- 回退：重新登录后清理**已核对属于本实验**的一次性探针任务；不改正式服务任务，不自动注销当前会话。

## D05 主机重启

- 执行：D06备份已实际通过，维护者选定重启窗口；先记录D05 running并同步Git。由维护者重启NUC，Agent恢复后重新读取run与待完成项。核对系统启动、任务启动、应用就绪和登录时间，必要时另一设备/启动后探针观察登录前服务。
- 通过：不依赖人工运行exe即可启动；启动时间与任务/日志可对应，登录前或无人交互期间服务存在证据；账号、项目、审核历史、定稿、素材和导出一致，无两个同根进程。
- 证据：重启前后probe、主机启动/任务/服务时间线、维护者确认、数据核对。不能把“重启命令已发出”当完成。
- 回退：任务失败时保持loopback手动运行原程序并查日志/权限，runtime不覆盖；没有观察无人登录阶段时保持未验收。

## D06 实际计划任务备份与恢复

- 执行：确认真实队列结束/可恢复、停止新操作；用当前backup_windows_task.ps1的ExecutablePath执行全新目录备份。核对任务恢复原状态、备份完成标记/哈希；停测试恢复实例，恢复到新目录，显式runtime/data/log、另一端口启动，核对登录、ACL、人工历史、素材和导出。
- 通过：不是运行中复制app.db；完整清单/SQLite/文件核验通过，至少一批实际数据一致；原任务/服务恢复预期状态。故意失败目标使用已有目录等可控条件，失败不能标成功且不覆盖已有数据。
- 证据：备份量/开始结束、命令、任务前后状态、恢复数量/哈希/登录与导出观察。只有mock测试不通过本项。
- 回退：保留原runtime、备份和程序；实验恢复目录独立。清理只处理已确认的实验副本。

## D07 异常退出与单实例

- 执行：在合成独立runtime/随机端口，通过test_deployment中的`test_cli_process_restart_full_flow_and_verified_backup`、`test_worker_recovers_claimed_job_after_process_kill`验证重启、第二进程拒绝、被认领任务被kill后的恢复；查看实际子进程和数据结果，不对正式生产服务kill。
- 通过：无两个数据根所有者；异常后可恢复队列/文稿/导出，迟到结果不覆盖人工更新。任务外部副作用可能重跑必须有责任说明，不承诺模型恰好一次计费。
- 证据：该两项在NUC当次真正执行/通过、进程/队列/文件结果。可以复用L01同一次日志，但声明证据重叠，不增加独立总数。
- 回退：仅合成实例，失败保留目录/日志定位后修复；原实例不动。

## P01 实际HTTP与主机资源基线

- 执行：三档实际账号已改密，从NUC本地交互终端运行HTTP探针，密码仅本机提示输入。它只读授权项目，登录/退出仅操作本次会话，不触发模型/渲染。另在不同终端启动资源trace，ProcessId取实际exe进程（有多个先查清）：

```powershell
python scripts/nuc_http_probe.py --base-url http://127.0.0.1:8000 --logins admin maintainer member --duration-seconds 60 --output "build/nuc-acceptance/$wenshuRun/P01-http.json"
.\scripts\windows_resource_trace.ps1 -OutputFile "build/nuc-acceptance/$wenshuRun/P01-resource.csv" -DurationSeconds 60 -IntervalSeconds 5 -ProcessId 12345 -MachineRole nuc
```

- 通过：三身份真实HTTP验证且无认证/请求错误；至少100次成功读、各身份均有样本，P95≤500ms；持续采样可用内存不低于4GiB，缺关键计数器/目标进程时补证，不把空值作0。HTTP JSON标记范围是基线读负载，不以它证明创作/渲染能力。
- 证据：样本数、间隔、实际耗时、JSON/CSV、同时运行的其他应用/Agent负载。系统CPU/磁盘是整机值；进程CPU秒为累计量，按增量/时间/核心数解释，不混为瞬时百分比。
- 回退：结束探针/trace，注销其测试会话；不修改项目。少于100请求或一身份失败就补跑/定位，不能只看退出0。

真实账号密码由成员/维护者在本机交互终端输入，不发送给Agent或提交Git。Agent没有交互输入条件时，让维护者运行上述命令并返回去敏JSON/CSV；缺项记录为“需要本机密码提示操作”，其他隔离验证继续。

## P02 持续工作、模型与渲染

- 执行：30～60分钟，三人/独立浏览器会话操作10～20主题：并行浏览/编辑、素材查看，连续排队创作、人工退回/批准和四平台导出；使用真实模型时记录费用与外部等待。同时运行资源trace（例如DurationSeconds1800），记录队列接受/开始/结束、模型/渲染时间，并核对实际成品。
- 通过：无越权、静默丢稿、审批错绑、定稿被改或不可恢复失败；持续工作期间运行HTTP探针，所采样的授权读取API维持P95≤500ms，可用内存不持续低于4GiB。写入/任务接受/渲染延迟另外记录，不把读取P95推广为所有接口。CPU>90%连续5分钟、内存持续增长、磁盘排队或吞吐骤降必须定位；正常单任务排队不当故障，外部网络/模型延迟单列。明显瓶颈未解决不得标通过。
- 证据：实际工作时长/主题数/角色并发、任务时间线、HTTP与资源样本、错误/重试/成品核对、模型渠道及成本摘要（不含密钥/正文）。NUC温度/频率若无可信采集，标未测，不编造温度。
- 回退：先停止新任务，保留数据/日志，恢复临时设置。纯无密钥降级测试不能代替真实模型质量，后者由R05明确验收。

## R01 跨网络HTTPS、Cookie/CSRF/SSE

- 执行：记录家庭上行、运营商/NAT/IPv4/IPv6是否已查、所选私有组网/证书/版本与使用条款。应用保持loopback并通过已授权HTTPS入口访问；至少另一独立网络测试登录、真实Secure/HttpOnly/SameSite会话、正常写/无CSRF拒绝、SSE事件/断线重连、图片与下载。
- 通过：独立网络实际可达且证书受信任；无未授权目录/数据库/备份暴露，共享访问令牌不能绕过成员；SSE不过度缓存且撤权后停止后续交付。只同机HTTP不算本项。
- 证据：去敏网络/代理拓扑、真实响应属性与拒绝码、断线重连和撤权事件时间线；Cookie/Token值省略。
- 回退：关闭对外入口/所选代理，保留loopback；外部条件未定时blocked，Windows本机项照常推进。

## R02 真手机和蜂窝

- 执行：实际手机型号/OS/浏览器或App版本，Wi-Fi与蜂窝各一次；登录、图片/长文、工作列表、退回/批准、下载、断网重连，按项目权限观察。记录手机组网客户端是否安装/版本。
- 通过：关键操作可完成、权限正确、无不可恢复排版/输入问题；蜂窝网络确实独立于家庭Wi-Fi。模拟390×844仅作辅助。
- 证据：操作者确认、实际设备/网络/时间、操作与耗时、必要去敏截图。
- 回退：退出会话；仅测试项目。没有实际手机/蜂窝就blocked。

## R03 外地成员协作

- 执行：至少一名外地真实成员和另一城市/运营商网络参与30分钟；共享项目分工、创作/审核/自审、退回修订、维护定稿、下载，与另一成员冲突保存，再由管理员对测试授权进行撤销并检查旧链接/SSE。
- 通过：真实跨城闭环完成；无法查看未授权项目；冲突输入保留；撤权后新请求/后续事件拒绝。已经下载内容不可撤回，不误报为可远程删除。
- 证据：别名/角色、城市/网络类型（不需要公网IP）、双方确认、实际状态/时段/失败与重试。

## R04 另一设备与实际RPO/RTO
