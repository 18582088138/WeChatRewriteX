# 文枢 V1.0+：本地小主机上的团队协作基础开发计划

日期：2026-10-30。状态：待开发；本文不代表任何功能已实现。

## 1. 已确认目标与范围

- 面向小团队，成员主要在中国大陆，跨城市或居家访问。
- 使用用户家中的小主机部署，开展功能与协作验证，暂不租云服务器。
- V1.0+ 独立建设应用基础；完成后再开发 V2 音频与 V3 视频。
- 本对话只制定计划；功能开发、部署与验证由后续新对话执行。
- 以现有 v1.0 正式版和后续实际工作区状态为基线。产品阶段名 V1.0+ 不作为语义版本字符串；软件版本遵守 docs/release/VERSIONING.md。

V1.0+ 的完成目标：成员访问同一服务，共享授权项目和素材，完成创作、人工审核、修订、定稿和发布包导出；并发操作不静默覆盖，异常后能恢复，备份能还原完整项目。

暂以 2～5 人、一个团队、一个小主机、一个应用实例作为容量验证范围。实际人数和硬件由开发首阶段确认，不据此承诺容量。

本版包括：成员登录与权限、共享项目与素材、人工审核流转、并发保护、责任记录、家庭主机部署、受保护的远程访问、备份与恢复。

本版不包括：TTS/视频开发、全平台自动发布、实时共同编辑与光标同步、多租户商业化、原生移动 App、复杂审批矩阵、SSO、微服务和高可用集群。

## 2. 技术与业务边界

### 2.1 首版建议

保留 Vue + FastAPI + SQLite + 文件素材库的模块化单体。SQLite 由服务端单实例管理，成员只通过应用访问，不共享数据库文件，不用网盘同步运行中的数据库，不启动多个进程争用同一数据根。

现有 docs/ARCHITECTURE.md 明确要求一个 ASGI worker；V1.0+ 不通过增加 worker 数量来实现多人使用。保留已有任务所有权、版本/revision 检查、定稿快照、导出快照与文件归档契约。

PostgreSQL 作为后续数据库演进选项：出现多应用实例、独立任务执行节点，或实际负载显示不可接受的写入竞争时再评估。小团队账号与权限本身不强制要求更换数据库。若开发者提出立即迁移，应先说明 SQLite 特有全文检索、事务与版本重建的迁移范围、收益和验收成本。

部署目标优先选择已有主机系统可稳定维护的方案。若已有 Linux/Docker 环境，可优先用可重复容器部署；若已有 Windows，先验证现有运行方式与服务化，不在未确认用户意愿前要求重装系统。应用、数据、配置和备份分开管理，数据库及素材都落持久存储。

### 2.2 现有能力的复用与增强

- 现有 APP_ACCESS_TOKEN 是部署访问控制，不能作为成员身份；新增独立成员会话与授权机制。
- 现有 Agent 审稿是 AI/规则内容检查；新增的是人工审核流程，两者状态分别表达并关联版本。
- 现有 version/edit_revision、迟到 AI 结果保护和导出快照应复用，在多人环境补齐成员身份及权限。
- 现有 /files 的可登记文件约束仍保留，并增加项目/团队授权；不能让反向代理直接公开整个 resource 目录。
- 现有任务只保证其已定义的恢复语义，不承诺所有外部调用强制取消或恰好执行一次。

### 2.3 首版产品规则

一个团队有管理员和普通成员；每个项目有负责人，并给成员分配创作者、审核者或只读权限。角色可兼任。管理员的全项目管理能力必须明确展示并记录重要操作；普通成员不能因为属于团队就看到所有项目。

项目内素材受项目权限约束；团队公共素材作为明确的共享范围。复制公共素材到项目后保留来源与历史引用，不能直接引用其他私有项目的文件地址。

人工审核默认由被指派且有审核权限的成员完成；作者自审作为显式团队设置。自审、管理员例外放行和跳过 AI 检查均需留痕，不能绕过版本冲突。

V1.0+ 的最终产物仍为现有发布包导出，不新增正式发布 API。

## 3. 分阶段执行原则

按 S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7 推进。每阶段完成范围内验证、交付记录和检查点，再进入下一阶段。预计投入只是排期参考，应在 S0 后按硬件、现有实现与有效开发时间重估。

涉及真实小主机的操作，应先确认具体设备和访问条件。开发者可以先完成本地实现、部署材料和自动化验证；不能把未实际连接的设备报告为已部署，也不能把未完成的远程访问报告为验收通过。

每阶段输出：已实现范围、验证证据、遗留问题、数据/配置变化、升级与回退方式。功能完成和真实环境验证分别记录。

## 4. S0：基线确认与实施设计

**目标**：确认设备、现有实现和业务规则，形成后续可执行基线。

**前置**：阅读仓库当前说明与未提交变更，不覆盖用户已有工作。

**工作内容**

1. 读取 AGENTS.md（如存在）、README、docs/PROGRESS.md、docs/ARCHITECTURE.md、部署与版本文档，核对当前分支、版本和已完成能力。
2. 记录小主机 CPU 架构、内存、可用磁盘、系统、Docker/服务管理能力；确认是否还承担其他应用、能否常开。
3. 记录家庭上行带宽、路由器条件、是否有公网 IPv4/IPv6、是否处于运营商 NAT；公网 IP 不是本版强制前提。
4. 确认首批成员数量、管理员、项目可见范围、作者自审策略，以及维护负责人。
5. 完成人员/项目/素材/审核/审计数据方案与接口权限清单，说明既有状态机的复用方式。
6. 选择部署方式、验证数据集、备份位置与远程访问候选路径。默认先做局域网；远程路径在 S6 验证后定稿。

**验收标准**

- 形成设备与网络信息、权限规则、数据迁移方案及阶段实施清单。
- 为旧项目、旧素材、历史定稿、AI 审稿和未完成任务明确迁移处理规则。
- 运行与当前基线相匹配的现有检查，记录通过、失败或环境限制，不能只引用旧文档的测试数量。
- 待用户补充的信息逐项列出；不依赖该信息的开发继续，硬件部署等依赖项保持待验证。

**预计投入**：0.5～1 个开发日，信息补充时间另计。

## 5. S1：单机运行与数据持久化基础

**目标**：现有图文应用先在可控环境中稳定运行，不开放公网。

**前置**：S0 运行路线明确；设备未就绪时可先完成开发机上的等价验证。

**功能实现**

- 开发/测试/主机环境配置分离；持久数据、配置、密钥和日志不随应用包替换丢失。
- 单实例约束、进程自动启动与异常重启；保留 health/ready 与任务日志。
- 从现有安装方式整理可重复部署流程，镜像/包尽量在开发机或构建环境生成，避免每次在小主机编译。
- 创建独立测试数据根；真实迁移前执行完整离线备份。
- 明确服务内网监听和访问范围；此阶段仅维护者验证，不以共享令牌替代团队账号发布使用。

**验收标准**

- 新建主题，走通收集、创作、AI/规则审稿、编辑、定稿与四平台现有发布包导出。
- 重启应用后项目、素材、文稿、定稿和任务记录保留；程序升级不会替换用户配置和数据。
- 第二个进程不能同时占用同一数据根；ready 状态能反映不可用组件。
- 异常退出后可按现有语义恢复任务；外部调用重试可能产生额外费用时记录其边界。
- 主机未实际验证时，交付状态明确写为“部署材料/等价环境验证完成，真实主机待验证”。

**预计投入**：1～2 个开发日，不含设备接入与硬件故障处理。

## 6. S2：成员账号、会话与权限基础

**目标**：将服务访问区分到具体成员，为所有业务入口提供授权基础。

**前置**：S1；此阶段仍不对外邀请团队使用。

**功能实现**

- 首次管理员初始化；管理员创建、禁用成员及管理权限，无公开自助注册。
- 成员登录、退出、密码更改和管理员辅助重置；密码使用成熟哈希库保存，日志不记录密码或会话凭据。
- 成员会话、安全 Cookie、退出/禁用后的失效与基本登录尝试限制；Cookie 认证的修改请求有适当防跨站保护。
- 团队设置、模型渠道、密钥、运行设置仅管理员访问；普通成员可以使用获准的生成能力，不能读取或导出密钥。
- 项目级授权基础；接口、列表、搜索、任务、SSE、素材预览/下载和导出都纳入权限清单。
- 保留最后一个可用管理员的恢复路径，避免误禁用导致无人能管理。
- 明确旧共享令牌模式的兼容范围；团队部署中不能用共享令牌绕过成员身份。

**验收标准**

- 至少管理员 A、创作者 B、审核者 C、无项目权限成员 D 四个测试身份。
- 未登录不能读取项目、素材或任务；D 猜测 ID、复制文件 URL、订阅事件、搜索关键词均不能获得项目内容。
- B/C 不可修改管理员配置、获取密钥；通过直接 API 请求也不能绕过界面限制。
- 退出和禁用后，会话不能继续执行受保护操作；活动事件连接不再泄露更新。
- 图片/视频预览、下载和 SSE 在合法登录下可用，不依赖 URL 内长期令牌。

**预计投入**：2～3 个开发日。

## 7. S3：共享项目、素材与历史数据迁移

**目标**：成员共享明确授权的项目，同时完整保留既有个人数据。

**前置**：S2。

**功能实现**

- 项目负责人、协作者、审核者/只读成员；项目列表按权限过滤，负责人可以在允许范围内管理成员。
- 项目成员移除、负责人转移及归档规则；禁止留下无负责人项目而无人可接管。
- 项目内资料与团队公共素材明确区分，公共/项目素材的复制保留原有去重、归档和来源关联。
- 项目访问范围覆盖历史文稿、定稿、素材、导出包、任务进度、审稿和费用，不只保护最新正文。
- 旧项目默认归初始管理员，先保持私有；旧公共库由管理员确认共享范围后再开放，避免迁移时自动扩大可见范围。
- 记录任务发起人、项目归属与结果版本；退出页面不影响后台任务。
- 成员撤权后立即失去读取与修改权限。已执行的外部请求按能力完成或标记中止，排队任务再次检查权限；结果只按当前项目权限提供访问。

**验收标准**

- B/C 共享项目 P1，B/D 共享项目 P2；C 不可读取 P2，D 不可读取 P1。
- 成员移除后通过旧页面、旧 URL、历史版本和文件链接都不能继续访问。
- 旧项目的文稿、引用、定稿、归档素材与发布包可读；分配协作者后再对其开放。
- 复制公共素材不修改原文件；项目改名、素材归档和历史引用继续符合原契约。
- 数据迁移重复启动不重复创建成员或归属，失败可恢复到完整备份；记录实际迁移与回退步骤。

**预计投入**：2～3 个开发日。

## 8. S4：人工审核与定稿流程

**目标**：明确谁审核、审核了哪一份内容、作者如何处理意见。

**前置**：S3；以现有工作版本与定稿系统为基础，不重新制造两份正文数据源。

**功能实现**

- 人工流程：编辑中 → 待审核 → 退回修改/审核通过 → 定稿；保留 AI/规则审稿的独立状态。
- 创作者选择审核者，提交具体不可变快照，保存提交人、版本/revision 或内容摘要与时间。
- 审核者针对段落、图片和文稿元信息给意见；支持待处理、已解决、不采纳及说明。
- 作者修订后重新提交；撤回提交、审核人变更、作者自审和管理员例外动作有明确权限及记录。
- 审核通过绑定明确版本。正文、标题、图片、素材引用等会影响成品的变更触发复核；评论处理状态等非内容操作不无故使审批失效。
- 过期评论仍可查看，但不能将旧版本的自动修改盲目应用到最新正文。
- 定稿同时检查当前人工批准、已有规则/AI 审稿策略与版本有效性；管理员例外必须注明原因，不能绕过并发冲突。
- 导出绑定已定稿快照；后续编辑不改变已排队导出的内容。

**验收标准**

- B 提交，C 退回，B 修改并重新提交，C 批准，B 按权限定稿并导出，全过程记录完整。
- C 批准旧快照时，若 B 已修改最新正文，不能把新正文标记为审核通过。
- 未指派或无审核权限的 D 不可审批；AI 审稿完成不会自动变成人工批准。
- 已批准内容修改后定稿准入正确变化；旧定稿仍能查看，不能被直接修改。
- 导出和人工批准引用同一有效内容版本；旧导出不能覆盖更新内容的导出。

**预计投入**：2～4 个开发日。

## 9. S5：多人并发、任务责任与协作记录

**目标**：多人同时工作时保留修改，明确任务与操作责任。

**前置**：S3/S4。

**功能实现**

- 复用服务端版本/revision 检查，新增编辑占用提示；若采用租约，提供超时和失联释放。
- 保存冲突时保留本地输入并展示可恢复路径，不能自动用最新服务端内容覆盖未保存修改。
- 对 AI 修复、整篇重写、回滚、采纳意见、定稿、归档等入口统一校验权限与版本。
- 工作中的 AI 结果若过期，按现有能力标记冲突或保留为候选，不静默覆盖新内容。
- 任务展示发起人、状态、失败原因、耗时及已有费用；费用统计按项目授权可见，管理员可查看团队汇总。
- 操作记录包括成员、对象、时间、动作与结果；权限变更、提交/审批/例外、定稿/回滚/归档/导出等必须留痕。
- 成员工作列表：待我审核、被退回项目、生成失败任务；通知先采用站内列表，无须本版接入飞书或短信。

**验收标准**

- B/C 打开同一版本，B 保存成功后 C 保存被识别为冲突，C 原输入仍可恢复。
- 用户关闭浏览器或断网后不会永久锁住项目；不同项目可以各自编辑。
- AI 等待期间人工改稿、回滚或定稿，迟到结果均不会覆盖当前内容。
- 重复点击提交/审批/导出不会产生不明确的重复状态或破坏既有任务准入。
- 成员权限撤销与同时执行操作的边界有测试；审计记录不泄露密钥和会话。

**预计投入**：2～3 个开发日。

## 10. S6：家庭小主机上的跨网络访问与运维

**目标**：让外地成员通过受保护入口稳定访问，并能维护和恢复家庭主机。

**前置**：S2～S5 的授权与协作验收通过；已获得实际小主机访问条件。

**功能实现/部署工作**

- 按 S0 信息确定远程路径：优先验证受保护私有组网；若成员不能安装客户端，再评估带身份控制的访问通道；具备合适公网条件时可评估 HTTPS 公网入口。
- 远程方案需验证国内连接质量、商业团队使用范围、客户端安装与移动端体验；不预设任何品牌免费且可用。
- 公网入口只暴露受保护的应用，数据库、素材目录、备份、管理配置和调试端点不公开。
- 代理层支持 Cookie、SSE 长连接和素材下载；断线后界面通过 API 重建状态，不依赖事件全量重放。
- 服务开机自启、异常重启、健康检查和受限资源并发；防止主机休眠导致团队不可用。
- 明确服务离线、外部模型失败与用户未授权的不同提示。
- 建立一致的数据库+素材+必要配置备份。初版优先复用离线备份契约：暂停接新任务、等待任务退出或进入可恢复状态、停服务备份再启动；说明维护窗口，不能直接复制运行中的 WAL 数据库主文件。
- 备份建议每日一次，至少一份保存在另一设备/异地位置，避免与小主机一起损坏；密钥备份限制访问，保留量由磁盘实测决定。
- 写出部署、升级、回退、查看日志、磁盘不足、备份失败和管理员恢复步骤。

**验收标准**

- 至少两种独立网络完成访问，例如家庭宽带与手机蜂窝网络；至少一名外地成员验证实际协作流程。
- 手机完成登录、素材预览、查看待审稿和审批，不要求完整移动端编辑器。
- 远程访问合法用户可用，未授权文件/事件/API 仍不可访问；第三方通道身份校验不替代应用项目授权。
- SSE 断线、页面刷新和重新登录后状态正确；大文件下载与任务超时表现有实际记录。
- 应用异常退出与主机重启后可自动恢复；真实断电测试按设备安全条件安排，不强行拔电。
- 在隔离目录/环境恢复一次备份，验证项目、历史定稿、素材、引用、成员权限和导出；不覆盖运行中的唯一原件。
- 初始运维目标：备份数据损失窗口不超过 24 小时，人工介入后恢复约 60 分钟内。两项是待实测目标，须同时记录数据量、操作步骤和时间，达不到则调整策略或目标。

**预计投入**：2～4 个开发日，家庭网络与账号申请等待另计。

## 11. S7：团队试运行与版本交付

**目标**：把阶段功能整合为可持续使用的 V1.0+。

**前置**：S0～S6；真实远程访问未完成时不能宣称团队版最终验收。

**验证范围**

- 测试成员至少覆盖管理员、创作者、审核者、无项目权限成员；测试项目至少覆盖共享、私有、迁移旧项目和归档项目。
- 使用约 10～20 个代表性真实主题；保留固定验证集，避免每次只测一篇理想文章。
- 按实际成员数测试并行浏览、编辑、素材查看与排队任务；不把排队当作故障，不要求所有生成任务同时运行。
- 完成一轮退回修订、一次批准后改稿、一次并发冲突、一次 AI 迟到、一次权限撤销、一次升级回退与一次备份恢复。
- 保留现有图文导出、来源引用、历史版本、归档素材等回归检查；针对新增权限、审批状态、迁移与故障边界补有意义的自动化与真实浏览器验证。
- 试运行建议 3～7 个自然日；记录访问失败、任务失败、修改丢失、权限问题、资源峰值和维护操作。

**版本验收门槛**

- 无未解决的越权访问、静默覆盖、错误审批绑定、定稿被修改或历史引用损坏。
- 真正跑通远程成员协作、重启恢复和隔离恢复演练，证据可复查。
- 性能门槛在 S0/S1 按主机与网络基线定义；区分页面/API 响应、网络传输和外部模型等待，不用统一耗时掩盖问题。
- 普通成员无法取得系统密钥；运行配置与成员权限的边界明确。
- 部署材料、版本、数据库迁移和文档与最终实现一致；软件版本按现有流程确定。

**交付物**

- 可安装/部署的版本与配置示例（无真实密钥）。
- 管理员/创作者/审核者操作说明，人工审核与例外处理规则。
- 部署与维护手册、备份恢复与回退说明。
- 阶段验收记录、试运行问题清单、尚未验证能力及 V2 可复用基础。
- 更新 docs/PROGRESS.md、相关架构/部署/使用文档和本计划状态；不把未来方案写成已实现。

**预计投入**：1～2 个开发日整体验收与修复，试运行自然日另计。

## 13. 新开发对话可直接使用的任务说明

请按照 docs/dev-plan-v1-plus.md 开发文枢 V1.0+ 团队协作基础。目标是部署在我家中的小主机，供主要在中国大陆、跨城市的小团队共享项目和人工审核；暂不租云服务器。

先阅读 AGENTS.md（如存在）、docs/PROGRESS.md、docs/ARCHITECTURE.md、docs/release/DEPLOY.md 和版本规范，核对当前工作区与正式版基线，尊重已有未提交改动。按 S0～S7 分阶段执行；S0 先确认设备、网络和团队信息，不假设可以重装系统或已经获得小主机访问。

优先复用 Vue/FastAPI/SQLite、单实例任务运行、版本/revision 检查、素材归档和导出快照。新增成员身份、项目权限与人工审核，不把共享访问令牌等同成员账号，也不把 AI 审稿等同人工批准。PostgreSQL、独立 worker 和实时共同编辑不作为本版强制目标。

每阶段完成实施与相关验证后汇报功能、证据、数据变化、遗留问题和回退方式，再继续下一阶段。代码完成、等价环境测试、真实小主机部署和外地成员验收分别标记，不能把未实际执行的验证报告为通过。TTS、视频和自动发布不在本版开发范围。
